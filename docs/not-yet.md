# Not yet

What this game does not do yet.

- **A Workshop map is a course document, not a scene.** `provides.json` accepts kind `map`, `map_kind` `obstacle` and `race`. The entry is `{"kind": "map", "map_kind": "obstacle", "scene": "<path>.json"}`: `scene` names the same JSON document `courses/` holds (see the maps repository's authoring notes). The document is the whole map (`pieces`, `checkpoints`, `finish`, `route`), so a pack ships no code. `WoCatalogue.follow_content` re-reads the index on every `playable_courses()`, so solo lists and plays it as "Name [Pack]" in the M menu and the course vote, and an online session lists none; the game's own ids (including `wo_practice`) win.
- **A pack ships courses, never arenas.** A document of kind `arena` behind a pack map is refused (listed in `WoCatalogue.refused`): the final death's arenas stay the game's own, and the menus have no row for one.
- **A pack course cannot bring its own art or sound.** The document names roles, themes and toys from the game's own sets (`WoTextures`, `WoAudio`, dot-props); there is no path field for a pack texture or stream, so a pack course uses the shipped look. Adding one is a document-format change (validator, builder and the copy that travels to clients), not an addon change.
- **A pack course claiming an id of the game's own can show on the ballot.** The catalogue keeps the game's course, but dot-vote's `follow_content` only de-duplicates against the ids in the source's own list, which leaves `wo_practice` out once there are other courses. The row reads "Name [Pack]"; choosing it is harmless because `WoGame` plays a next course only if the catalogue lists it. Fixing it needs a reserved-ids list on `DotVoteListSource`.
